# 安全与业务修复说明

本轮对应 2026-11-10 审查报告的 20 项发现。生产部署采用服务端名片模式，证书仍由 Nginx Proxy Manager 管理。

## 修复对应表

| 审查项 | 修改 |
|---|---|
| S01 转发头与限流 | API 默认不信任转发头；Docker 显式指定可信代理，项目 Nginx 覆盖转发 IP。限流状态有 TTL 和容量边界 |
| S02 旧口令头 | 移除 `X-Card-Token` 鉴权，只接受服务器会话对应的 Bearer token |
| S03 无签名旧名片 | 服务端模式拒绝 hash 名片；有效短码附加 hash 不能覆盖数据库记录 |
| B01 删除失败丢索引 | 仅在删除成功或记录已不存在时移除索引，界面按服务器权限展示操作 |
| S04 停用缓存 | API 与前端请求均不缓存；名片页恢复可见时校验状态，可见期间每 30 秒刷新 |
| S05 会话撤销 | 会话保存在数据库，退出时撤销；角色口令参与签名，改口令使该角色旧会话失效 |
| S06 相同口令 | 生产拒绝相同、过短或占位凭据，部署脚本同时校验 |
| S07 头像规则 | 只接受有限大小的 JPEG/PNG，服务端解码、限像素并重编码为 180px JPEG，不接受外链头像 |
| B02 500 条上限 | 管理列表按服务端搜索与分页，返回真实总数，支持超过 500 条 |
| B03 共享 IP 配额 | 成功登录不占错误口令预算；建卡配额按恢复身份和业务时区持久化统计，IP 另作短时保护 |
| B04 本地分享 | 本地模式仅提供本机预览，不显示可跨设备分享的短链二维码 |
| B05 我的名片 | 新名片归属于恢复身份，列表从服务器取回；无 20 条截断，恢复码可跨设备/域名登录恢复 |
| C03 长二维码 | 隐藏与可见二维码使用相同的模式与容量保护 |
| D01 Node EOL | Docker 使用 Node.js 24；开发工具需 Node.js 22.12+。Nginx 明确锁定 1.30.6，避免镜像源的移动标签停留在旧版本 |
| D02 依赖公告 | 升级 Vite 8、React Router 7、兼容插件及锁定依赖 |
| D03 假成功 | 部署健康检查失败返回非零状态 |
| D04 明文日志 | 部署仅显示凭据文件位置，不输出口令 |
| D05 初始化恢复 | `bootstrap.py --resume` 使用原配置继续，不重置现有用户口令；先验证凭据再授权 |
| C01 错误处理 | 非法 JSON 为 400，超大请求为 413；健康检查不回传数据库内部错误 |
| C02 空名片入口 | 缺少短码或有效数据时显示无效链接提示，结束加载 |

另增加名片资料编辑：本人或管理员可修改联系方式、职位与头像，原短码和二维码保持有效。地图导航使用展示的公司地址。

## 恢复码与权限

首次登录时浏览器生成随机恢复码；服务器只保存其摘要。新名片按该恢复身份归属，业务员只能编辑、删除自己名片，管理员可管理全部名片。业务员不能停用其他名片，也不能根据一个公开短码取得管理权限。

在控制台「跨设备恢复我的名片」中复制恢复码并私下保管；在另一台设备或另一域名登录时填写恢复码和访问口令，即可恢复服务器上的本人名片。恢复码属于私密凭据，不要提交到仓库或放进公开名片链接。

历史名片没有可信的归属信息，升级后仍由管理员维护。管理员可在列表选择「分配归属」，输入本人提供的恢复码，明确分配管理权限。旧浏览器中已有的索引保留读取入口，不会因为知道公开短码就自动获得编辑或删除权限。

## 数据迁移与升级

启动会执行可重复的新增迁移：

- 为 `cards` 添加可空 `owner_key` 和索引，保留现有字段、记录与短码。
- 新建 `card_sessions` 存储会话及撤销状态。
- 新建 `card_daily_usage` 原子统计每日配额；过期会话和较久以前的配额记录会清理。

升级前备份数据库和私有 `.env`。旧版本 token 需要重新登录；口令无需为本次升级更换。旧数据不会被自动认领。部署后执行 `python3 deploy/verify-deployment.py`，检查管理员列表中的历史数据。

`TRUST_PROXY` 必须与实际代理链匹配。Docker 默认信任回环及私有代理网络；最外层代理必须覆盖客户端传入的 `X-Real-IP`，项目 Nginx 会清洗转发链。若共享网络内包含不可信容器，应将 Nginx 的可信来源与 API 配置收紧到实际代理地址。直接运行 API 时默认使用 `TRUST_PROXY=false`。

## 测试

```bash
npm ci
npm --prefix server ci
npm test
npm run build
```

真实数据库回归入口为 `server/test/mysql-integration.mjs`，只允许显式设置 `RUN_MYSQL_INTEGRATION=1` 且数据库名称符合 `zhongju_test_<随机值>` 的隔离环境。它会验证旧表迁移、并发配额、分页、转义搜索、归属和会话，不应连接业务数据库。

## 尚需产品决策的能力

恢复码是可迁移的设备身份，并非企业实名员工账号。独立员工账号、逐人停职撤权、审批、完整操作审计、软删除恢复、个人信息保留期限以及微信真实设备分享效果，仍需单独设计和验收。共享角色口令无法代替这些能力。

新访问会重新校验名片状态，但已经保存的海报、截图和已展示的联系方式无法远程撤回。可见页面的状态刷新也不等于撤回已经交付给访问者的内容。
